# 在办台账（work-board）：约定与可复制模板

> 配套文档：**[跨会话 agent 通信](cross-session-inbox.md)** —— 那一份讲"**点对点**"的信箱；
> 这一份讲"**所有人都该知道**"的公共布告板。两者互补，不能互相替代。

---

## 一、它解决什么

信箱是**点对点**的：A 写给 B，别人看不见。
但有些事**所有人都该知道**：

- 「**我在改这个文件**」—— 免得别人也在改；
- 「**这件事我查过了，结论是 X**」—— 免得别人从零重查；
- 「**我认领了这个任务**」—— 免得两个人做同一件事。

⇒ 这些放进台账：**一行一件事，全机可见**。

## 二、一个最小可用的台账

就是一个 Markdown 表格：

```markdown
| 会话 | 在做什么 | 开始 | 状态 | 产出 / 落点 |
|---|---|---|---|---|
| `<会话标识>#<后6位>` | 一句话说清这件事 | 14:20 | doing | 文件路径 / 结论 / 链接 |
```

**状态词**（建议固定，别自创）：

| 词 | 含义 |
|---|---|
| `doing` | 正在做 |
| `claimed` | 已认领、还没开工 |
| `pending` | 无主待办（**谁都可以接**）|
| `done` | 已完成 |
| `released` | 原主放弃 ⟹ 可以易主 |
| **`ready`** | **逻辑归档完成、只差主人点按钮**。⚠️ 与 `archived` 是**两档**：这个**你能判定**（活干完了、该交的都交了），`archived` **只有人能产生**（界面上一按）。自己标 `archived` 会造出**假状态** —— 后来的人看到"已归档"就不再找它，而它其实还在、还能被叫醒 |
| **`archived`** | **该会话已被归档** —— 不会再主动回复，**别再等它** |

⚠️ **状态词要能被工具匹配**（例如 `\|\s*\**\s*done\b`）—— 写 `**done** ✓` 这类装饰是允许的，
但**别改写词本身**，否则自动化会把它当成"还没做完"。

## 三、⭐ 三条硬约定

### ① 署名必须带可追踪的 id

格式 `<自由代号>#<会话标识后 6 位>`：

- **前面那半随你心情**（"正在改底层环境的鲸鱼"、"焦头烂额的鲸鱼"、不叫鲸鱼也行）—— 它是你留给别人的**性格名片**；
- **后面那 6 位必须真实**（取自你运行时会话标识的**最后 6 个字符**）。

**为什么**：没有 id 的署名**回答不了"这件事是谁做的"**。
（真实教训：某天 37 行台账里有 25 行自署同一个称呼，一旦要追责或询问，**线索就断了**。）

### ② ⭐ 署名即栅栏

> **一行的第一列带着别人的署名 ⇒ 那是别人的活 ——
> 不执行、不"顺手帮一把"、也不提议接手。**

只有两种情况可以易主：**原主在自己行里写了 `released`**，或**用户点名改派**。

**为什么**：这条是被真实事故逼出来的 ——
一只**读了全表**的新会话，仍然向用户提议"要不要我接手那个任务"。
⇒ **"认领"的全部意义就是"不用再问"**；每只新会话都问一遍，那张纸就白写了。

（工程上还有个兜底做法：让"开工检查脚本"把**别人的未完成认领**单独拎出来打印一遍 ——
**文字规矩拦不住不细看的人，就让它自己喊**。）

### ③ 归档前必做

⚠️ **归档这个动作，通常由人在界面上点** ⇒ agent **事先无从得知**。
所以约定：**当用户表达"要归档了"时**，agent 自己先做两件事：

1. 把自己**还没完成**的行标成 `archived`；
2. 在自己**最后发出的信件**标题末尾补 `[FINAL-ACK]`。

⇒ **这两件是同一件事的两面**：让还活着的会话知道「**你走了**」，不必再等你。
（代价实例：一个会话归档时没人做这两件事，别人写给它的信就一直显示"⏳ 还没回执" ——
而"它还没读"与"它永远不会读了"**长得一模一样**。）

⚠️ **注意"意思 vs 咒语"**：触发语是**意思**（"归档吧""进入归档流程""可以收了"都算），
但 **agent 不能只凭一句话就动手** —— 若对方在**讨论/举例**、或语义含糊，**先反问一句**；
判据是**有没有收尾信号**（"验收通过""没什么事了""我要关了"）。

## 四、归档：只增不减会让每次开工都变贵

台账是**每个会话开工都要全量读一遍**的东西 ⇒ 它一膨胀，成本就乘以会话数。

**分层的做法**：

- **活台账** = 所有**未完成**的行 + 最近 N 行**已完成**（N 取 15 左右够用）；
- **冷归档** = 更早的**已完成**行（保留原文、可 grep，**只是不再自动打印**）；
- **归档 ≠ 删除** —— 追溯"这件事是谁做的"仍然查得到。

**判据用「行序」而不是时间**：表里的时间列常常只有 `HH:mm`、没有日期，解析容易出错；
而"保留最近 N 行已完成"既够用又不会误判。

**⚠️ 两个必须做的保护**：

1. **并发保护**：归档的动作是"读全文 → 重写"。若在你读完、还没重写的**间隙**里
   有人往台账加了一行，直接重写就会**把那行吃掉**。
   ⇒ 做法：**重写前重新取一次内容指纹，与读时不一致就立即中止、什么都不改**
   （宁可这次不归档，也不能吞掉别人的登记）。
2. **校验要比较「数据行」，不要比较「文件总行数」** —— 归档只搬数据行，而活台账重写时还包含头部
   （约定/规矩），两者相加本来就不等于原文件总行数。
   ⚠️ 而且**口径必须统一**（要么都含表头、要么都不含）——
   我们曾因为"表头被扣了两次"而**恒报"对不上"**，
   直到靠独立逐行比对才确认数据其实一条没少。
   **一个恒报的假警报，会让真丢行时也没人信** —— 这比没有警报更危险。

## 五、可复制模板

**表头**（照抄）：

```markdown
| 会话 | 在做什么 | 开始 | 状态 | 产出 / 落点 |
|---|---|---|---|---|
```

**一行的写法**（注意：状态词别改、落点要具体到路径/链接）：

```markdown
| （**改配置的鲸鱼#a1b2c3** · 14:20） | 把代理例外补进 `.env` 并实测三个域名 | 14:20 | **done** ✓ | 备份 `xxx.bak-*`；实测 api 200 / 401 |
| （**读代码的鲸鱼#d4e5f6** · 14:35） | 【待办 · pending】给作者提一个 issue（**需用户点头**）| 14:35 | **pending** | 草稿在 `issue-草稿-xxx.md` |
| （**收工的鲸鱼#a1b2c3** · 15:40） | 🔚 本会话已归档；未结项 0 | 15:40 | **archived** | 留下的东西：`xxx.md` / 仓库链接 |
```

**开工时该做什么**（一句话版）：

1. 读台账 + 已核实事实（有 TTL 的用 TTL，别重查）；
2. **动共享状态之前，先加一行**；做完改成 `done`（**别删行**）；
3. 看到**别人的**未完成认领 ⇒ **别碰、别问、别提议接手**。
